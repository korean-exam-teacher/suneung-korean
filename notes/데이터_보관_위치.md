# 대용량 데이터 파일 보관 위치 안내

프로젝트 저장 용량(약 200만 토큰)이 가득 차서(2026-09-16), 대용량 JSON은
프로젝트 문서에서 빼고 사용자 컴퓨터의 USB(F드라이브)로 옮겼다:

```
F:\평가원 기출 문제 모음\문제은행_데이터\
├── items_final.json                  (1,492문항 — 2018~2027학년도 29개 회차 마스터 데이터, 정답 있음)
├── choices.json                       (선택지 원문 1,479건, 2015 교육과정 세트)
├── passages.json                      (지문 원문 371개 그룹, 2015 교육과정 세트)
├── ab_items_raw.json                  (2014~2016 A/B형 16개 문제지 + 2014 예비시행 2개, 총 810문항 — 정답 없음, 구버전)
├── ab_items_with_answers.json         (위와 동일 문항에 정답·배점 병합 완료, 예비시행 2개만 정답 없음)
├── items_2017_raw.json                (2017학년도 6/9/11월 3개 문제지 135문항 — 정답 없음, 구버전)
├── items_2017_with_answers.json       (위 135문항 전부 정답·배점 병합 완료)
├── items_2009_2013_raw.json           (2009~2013학년도 13개 문제지 585문항[6~50번] — 정답 없음, 구버전)
├── items_2009_2013_with_answers.json  (위 585문항 전부 정답·배점 병합 완료)
└── answer_keys_2009_2017.json         (2009~2017학년도 36개 시행 정답표 원자료: {exam_id: {문항번호: [정답,배점]}})
```

**다음 세션에서 이 데이터가 필요하면:**
1. 사용자 컴퓨터가 이 세션에 연결되어 있어야 하고(디바이스 브리지), 위 USB(F드라이브)가 꽂혀 있어야 한다.
2. `mcp__remote-devices__device_stage_files`로 필요한 파일만 컨테이너로 가져와서 작업한다(전체를 매번 프로젝트에 다시 올리지 말 것 — 용량 문제 재발함).
3. 스키마·필드 설명은 `claude/문제은행 파일럿 기록.md`, `claude/문제은행 파일럿 기록 - Stage12.md`에 기록되어 있음.
4. `device_commit_files`가 "written" 성공을 반환해도 실제로 USB에 반영이 안 되는 경우가 한 번 있었다(2026-09-16, ab_items_raw.json) — 중요한 파일을 옮긴 뒤에는 반드시 `device_list_dir`로 파일 크기까지 재확인할 것(이번 세션의 `_with_answers` 3개 파일 + `answer_keys_2009_2017.json`은 전부 재확인 완료).

**진행 상황 (2026-09-16 최신 기준):**

2009~2017학년도(구 교육과정 13개 시행 + A/B형 16개 시행 + 2017 통합 3개 시행 + 2014 예비시행 2개, 총 34개 문제지 1,530문항)의 지문·발문·보기·선택지·영역 확보가 전부 끝났고, 이번에 사용자가 USB `정답표` 폴더에 올려준 정답 자료(PDF 33개 + HWP 2개)에서 **36개 시행의 정답표를 전부 확보·전산화**했다(2009~2017학년도에 필요한 정답표는 36개 전부 — 100% 확보). 각 시행 배점 합계가 전부 정확히 100점으로 검증됨(2점짜리 오류 없음을 강하게 뒷받침).

- 정답 전산화 방법: 텍스트 레이어가 있는 PDF 29개는 pdfplumber로 직접 파싱, 스캔 이미지 PDF 7개는 페이지를 PNG로 변환해 육안으로 직접 읽어 옮겼다(이 환경엔 한국어 OCR이 없음). 2009.06·2009.09는 PDF가 아니라 구버전 HWP(한글 5.0) 파일이었는데, OLE 미리보기 스트림(PrvText)에 텍스트가 들어있어 자체 제작한 순수 파이썬 CFB 리더(`cfb.py`, 프로젝트에 저장돼 있음)로 직접 읽어냈다.
- **문항 텍스트와 병합 완료**: `ab_items_with_answers.json`(720문항 중 720 매칭, 예비시행 90문항만 정답표를 못 구해 미병합), `items_2017_with_answers.json`(135/135 매칭), `items_2009_2013_with_answers.json`(585/585 매칭). 즉 이번에 새로 추출한 문항 중 정답이 없는 것은 **2014 예비시행(A/B) 90문항뿐**이다 — 예비시행은 공식 정답표가 배포된 적이 없는 것으로 보인다.
- **아직 `items_final.json`(마스터)에는 병합 안 함**: `items_final.json`은 문항번호·정답·배점 외에도 소재·분야·유형·개편매핑_과목 등 항목별로 직접 분석해 채운 필드가 많다. 이번에 새로 뽑은 1,440문항(정답 있는 것)은 아직 이 분류 작업을 거치지 않았으므로, 숫자만 기계적으로 합치면 마스터 파일의 나머지 항목들과 품질이 안 맞는다 — 별도 세션에서 항목별 소재/분야/유형 분류를 거친 뒤 병합하는 게 맞다(정확성이 생명이라는 원칙상 이 분류는 지어내지 않고 지문을 직접 읽고 판단해야 함).
- **정답표를 못 구한 시행**: 2014 예비시행(A/B) 2개뿐. 나머지 34개 필요 시행(2009~2017, A/B 포함)은 전부 확보.
- **문항 텍스트 자체가 없어 정답표만 보관 중인 시행**: 2009.09, 2009.11, 2014.11.A, 2014.11.B — 문제지 PDF가 스캔 이미지라 지문·발문 추출이 불가능했지만(OCR 불가), 정답표는 이번에 확보했다. 나중에 텍스트 레이어가 있는 판본을 구하면 바로 병합할 수 있도록 `answer_keys_2009_2017.json`에 남겨 두었다.

**남아있는 작지만 중요한 발견 (해결 안 됨, 2026-09-16 기준):**
`문제은행 파일럿 기록 - Stage12.md`/`Stage13.md`는 `items_final.json`에 `보기`(제시 자료)·`역량` 필드를 추가했다고 기록하지만, 실제로 컴퓨터에 저장된(구 프로젝트본 그대로 백업된) `items_final.json`에는 이 두 필드가 없다 — 그 작업 이후 결과물을 다시 저장하지 않은 것으로 보인다. 웹사이트를 다시 빌드하기 전에 이 필드들을 다시 만들어 넣어야 할 수 있다(원래 스크립트/로직은 각 Stage 문서에 설명되어 있음).

**프로젝트에 남아있는 작은 데이터 파일들** (그대로 유지, 용량 문제 없음):
`items_2028_예시.json`, `choices_2028.json`, `passages_2028.json`, `choices_ebs_sourced.json` — 전부 45개 이하 항목이라 작음.
